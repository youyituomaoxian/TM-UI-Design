快速上手 · 5 步

第一次生成页面的最小路径
1 定位仓库 在项目目录内对话（AGENTS.md / CLAUDE.md 自动加载）；本目录即仓库根（main），git pull 取更新。TM_DESIGN_REPO 仅兼容旧入口。
2 脚手架起手 new-page-web.js（Web）或 new-page-mobile.js（移动）——自动克隆框架 + 注入克隆凭证 + 修 CSS link，落 ./output/。
3 填内容 按 RULES.md §1.1b 页面类型规格从零自建；组件用规范 class，颜色/尺寸/字重全走 var(--*)；图表按 CHART-SPEC.md。
4 过门禁 scripts/verify.js page <页面> → 0 HIGH（validate + 页面契约 + 组件复用 + 树运行时）；交付口径 scripts/verify.js all（页面契约 + 存量全链路 + 新规范范围）全绿；只验新规范用 --scope=new。
5 分享 运行 scripts/build-share-web.js <页面> 生成同名 _分享版.html——内联 CSS + 4 个 js + 本地资源并校验零外链；禁手工内联。重出后复跑单页门禁。

常见问题

踩过的坑，直接规避
▼为什么必须用脚手架 / 克隆 page-template？
page-template.html 是唯一框架来源。自搭框架或跳过克隆会被门禁拦截（template.clone.missing / framework.fingerprint，HIGH）——左右结构外壳（shell/rail/ws-global/ws-body + 作业树 + rail-foot）只有从真源克隆才不会漂移。
▼为什么「0 HIGH 才交付」？
HIGH = 会破坏视觉一致性或规范契约的硬伤（裸 hex、自造组件、KPI 错误排列、框架不完整等）。MEDIUM 可接受但建议清零。
▼换肤换什么、不换什么？
换：品牌色 primary 系（默认亮色；暗色固定不随品牌）——主题/语言入口在 `.ws-global` 工具区（调色盘 + 地球图标，模板自带；暗色 + 5 品牌主题）。不换：组件结构/尺寸/字阶/圆角、图表色 --chart-*、功能色（成功/警告/错误/运行）。引擎派生色只能出现在 :root 定义里。
▼data-species 是什么？需要我手动指定吗？
species 是与页面类型正交的维度，只有两种合法值：workbench（B 端工具页，含 .stat-grid 骨架）和 document（文档/说明页，如本页）。生成时 Agent 按 RULES §1.1c 自动判定并写入 body[data-species]——缺失记 MEDIUM、非法值拦 HIGH，你无需手动指定。
▼分享版为什么必须用脚本生成？
分享版 = `template.css` + 4 个运行 js（shell-ui / tree-nav / i18n / page-ui）+ 本地图片/logo 全部内联，零外链。手工只内联 CSS 会丢交互与图标，打开即坏——统一用 `node scripts/build-share-web.js <页面.html>`，脚本会校验零外链（残留外链 exit 1）。
