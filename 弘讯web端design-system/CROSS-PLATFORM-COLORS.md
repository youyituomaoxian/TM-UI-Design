# 弘讯跨端功能色契约（Cross-Platform Functional Color Contract）

> 目的：让 Web（B端后台）与 移动端（小程序/App）在「功能语义」上一致，在「平台实现」上各自最优。
> 适用范围：成功 / 警告 / 错误 / 运行·在线 四类状态色。
> 制定日期：2026-07-08

---

## 核心原则

1. **语义一致**：四类状态含义两端相同（成功=操作完成；警告=需注意；错误=失败/故障；运行/在线=设备正常运行）。
2. **平台分治**：Web 采用 Ant Design 功能色（文字密集、白底标签场景可读性更优）；移动端采用鲜亮色（小屏、户外、填充徽标场景更醒目）。
3. **运行绿共用**：「运行/在线」两端统一为 `#16A34A`——这是工业监控最高频状态，必须两端同色。
4. **禁止混用**：成功绿（Web `#389E0D` / Mobile `#10B981`）≠ 运行绿 `#16A34A`；状态指示灯/状态点一律用运行绿。

---

## 语义对齐补充（2026-07-28）

- **token 语义两端统一**：Web 端 `--suc` / `--warn` / `--err` / `--run` 现已统一为「**背景色**」语义（filled background），与移动端（`--suc` = 背景 `#10B981`）对齐。**同名 token 在两端含义一致**，跨端复用组件不再因语义歧义出错。
- **色值仍分治**（不混用）：Web 背景取 Ant Design 约定（成功 `#389E0D` 等），移动端取鲜亮色（成功 `#10B981`）。仅语义统一，色值各自最优。
- **Web 浅底 Tag**：用 `--*-soft`（浅背景，如 `--suc-soft` `#F6FFED`）+ `--*`（深绿字，如 `--suc` `#389E0D`）。
- **Web filled 白字场景**：用 `--*-fg`（白字，背景上的前景色，对齐移动端 `functional.*.text` 近白）。

## 配色表

| 语义 | Web (Ant Design) | Mobile (Tailwind 鲜亮) | 说明 |
|------|------------------|------------------------|------|
| 成功 Success | `#389E0D` | `#10B981` | 操作完成、校验通过 |
| 警告 Warning | `#FA8C16` | `#F59E0B` | 需注意、中风险 |
| 错误 Error | `#F5222D` | `#EF4444` | 失败、故障、告警 |
| 运行/在线 Running | `#16A34A` | `#16A34A` | 设备运行/在线（**两端同色**） |

## 派生色（Web 已注册变量）

运行绿已在 Web 颜色规范变量集中注册，共 3 个基础变量 + CSS 衍生：

| 变量名（语义） | HEX | 用途 |
|----------------|-----|------|
| 运行 · 文字 | `#16A34A` | 状态文字、状态指示灯、状态点 |
| 运行 · 背景 | `#ECFDF5` | 运行态 Tag / Badge 背景 |
| 运行 · 边框 | `#BBF7D0` | 边框 |

CSS 变量名（见 Web 端 `DESIGN-TOKENS.md` §2.6，短名统一）：`--run` / `--run-hover` / `--run-bg` / `--run-border` 等（`DESIGN-TOKENS.md` 由 `scripts/generate-design-tokens-md.js` 从 `tokens.json` 自动生成）。

---

## 使用红线

- 移动端鲜亮功能色**只作填充徽标底 + 白字**，不作白底正文小字（对比度不足）。
- Web 功能色严格用 Ardot 变量集，禁止硬编码 HEX；文字/标签场景优先用 Ant 文字色（可读性优于移动端鲜亮色）。
- 状态指示灯 / 状态点：在线/生产 → 运行绿 `#16A34A`；故障 → 错误红；空闲 → 辅助蓝 `#0A84FF`；离线/关机 → 灰 `#ADB5BD`。
- 成功绿与运行绿语义不同，不得互换。
