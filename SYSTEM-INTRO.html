S1 · 系统是什么 · ← → 切换页面

它解决什么问题

痛点 → 根因 → 方案
团队成员生成的页面长得不一样

不同人用 AI 出图，风格全靠自由发挥，没有统一基准。

同一个人每次生成都漂移

上次的颜色、间距、组件样式，下次记不住、对不齐。

同一个产品每个页面都不像同一套

页面类型规格缺失，表格/表单/看板各自为政。

组件 / 图标随手自造

按钮、标签、图标风格不统一，维护成本高。

根因

AI 没有「统一的设计基准」——全靠自由发挥。传统设计规范是给人读的文档，AI 读得慢、读不全、执行不一致。

方案：把规范变成机器可执行资产

设计令牌（唯一一套变量）

颜色/字号/间距/圆角/投影全部 var(--*) 化，AI 只能引用。

组件标准样式（禁自造）

按钮/表格/表单/图表用预定 class，链接 template.css 真源。

生成规范 + 门禁（0 HIGH 才交付）

AI 生成页面过自动检查，风格跑偏会被拦住并提示修复。

S2 · 解决的问题

工作原理：一套真源，两层保障

真源 → 克隆 → 填充 → 校验
设计令牌tokens.json + DESIGN-TOKENS.md
唯一配色/字阶/间距来源
视觉真源template.css 组件类
（四件源码 build 生成）
克隆源page-template.html 框架
顶栏/侧栏/底栏零改动
填充内容按 RULES §1.1b 页面类型规格
从零自建，组件走契约
门禁校验validate-spec.js 0 HIGH
ci-local 86 项全绿才健康

机器契约

components.json 组件规格契约（尺寸/色值/圆角/Ardot 映射），驱动门禁自动校验；tokens.json 机器格式令牌，与 template.css 一致有门禁。

风格一致性保障

所有页面 link 同一份 template.css；图标一律从 icons/ 取；颜色只用 var(--*)；数值列表格右对齐、表头 48px……写进规则 + 门禁双重锁定。

一处更新，全员同步

改视觉 = 改四件源码 → build 生成 template.css → git 推送 → 团队成员 git pull 即得最新规范（两端 CHANGELOG 记录变更）。

S3 · 工作原理

用法 A：AI 生成视觉页面（HTML 原型）

最常用 · 快速出原型 / 评审 / 对接开发
1
你说一句话需求

带上「用弘讯设计系统」+ 页面类型 + 关键内容。

2
AI 读设计系统规范

AGENTS.md → GENERATION-SOP.md → 对应端 RULES / components.json（按需检索，不通读）。

3
脚手架克隆框架 + 填充内容

node scripts/new-page-web.js 语义名 → 在内容区从零自建业务模块。

4
自动过门禁

validate-spec.js → 0 HIGH 才交付；报错就修，不跳过。

5
浏览器打开即看

产物落你项目的 output/；分享版内联 CSS 零外链，可发给任何人。

反面例子（会漂移，别这样问）

S4 · 用法 A

用法 B：AI 生成 UI 设计稿（Ardot 画布）

需要原生设计稿交付给设计师精修时用
1
你说一句话需求

带「用弘讯设计系统」+ 在 Ardot 里搭页面帧。

2
AI 读组件映射 + 搭建

在 Ardot 画布用组件库 + 变量 + 文本样式搭建页面帧（Web/移动端各一个组件库文件）。

3
截图自验 + 设计师收尾

AI 截图自检视觉，设计师在 Ardot 里手动精修交付。

前提（三者缺一就退回用法 A）

① 已安装并登录 Ardot；② 可访问 Ardot 组件库文件（Web / 移动端各一个）；③ AI 已连接 Ardot（MCP 插件）。

没有 Ardot 怎么办？

不影响 —— 直接用用法 A 的 HTML 原型，它就是「设计稿等价物」（可预览 / 评审 / 标注 / 交付开发）。Ardot 只是锦上添花的原生画布路径。

两路径对比

维度用法 A · HTML用法 B · Ardot
产出HTML 原型（可运行）原生设计稿
上手零安装需 Ardot + 组件库 + MCP
场景原型 / 评审 / 演示设计师精修交付
门禁0 HIGH 自动校验截图自验

例子

用弘讯设计系统，在 Ardot 里搭一个「移动端登录页」设计稿：顶部导航 + 手机号输入 + 验证码 + 登录按钮。

团队约定（第一道闸）

所有 AI 生成页面的话术里必须带「用弘讯设计系统」；KPI 卡只有图标卡/环形卡两种；颜色只用令牌；数值列右对齐；生成后必须过门禁。
