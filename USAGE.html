三个角色，三条链路，一份真源

规范和组件库已经完工。这一页只回答一件事：你这个角色，怎么让 Agent 替你产出符合弘讯设计系统的东西。 你说自然语言，Agent 读真源，产出视觉产物 —— 设计师拿设计稿，产品拿 HTML，前端拿 React。

2

共同前提

三个角色都绕不开的四条。

真源
弘讯web端design-system/ 和 弘讯移动端design-system/ 下的 tokens.json（值）+ components.json（契约）。冻结只读。
铁律
不硬编码色值；不自造规范；组件词汇与代码库同源（Web 33 件 / 移动端 NutUI）。
质量闸
HTML 产物 → validate-spec.js 0 HIGH； React 产物 → validate-static.js 5 门禁全绿。
禁区
不改真源 / 门禁 / 引擎。Web 端成功绿一律 #389E0D， 禁用移动端那支成功绿；运行/在线绿 #16A34A 两端共用（≠ 成功绿）。
不合格： 改门禁放松判定、内联 style 或 !important 绕过组件规则、 从产物（设计稿 / HTML / 代码）倒推 spec。发现规范本身有 bug —— 写 BLOCKED.md，不要顺手改。

UI 设计师 → 设计稿

工具中立：Ardot、Figma、即时设计、MasterGo、Pixso 均可 —— 只要 Agent 能读规范、能操作画布。

UI 设计师Agent + UI 设计工具 → 设计稿
1怎么对 Agent 说
按弘讯设计系统规范，在 <设计工具名> 里搭建 <页面描述>。
规范读 弘讯web端design-system/ 的 tokens.json、components.json、MASTER.md。
颜色必须绑变量或严格等于 tokens.json 的值，禁止裸 HEX；
组件结构与命名对齐代码组件库。
选端Web 写 弘讯web端design-system/，移动端换 弘讯移动端design-system/ 起手先读规范再开画布 门禁0 裸 HEX + 词汇同源
2Agent 读什么（按顺序）
顺序文件取什么
1tokens.json色板 / 字阶 / 间距 / 圆角 / 阴影的值
2components.json组件结构化规格（尺寸 / 状态 / 变体）
3MASTER.md布局规则（Web 顶栏 72 / 侧栏 240；移动端 375 宽 / 落位 343）
4RULES.md（含 §1.1b 页面类型规格）组件选型 + 页面覆写规则
3怎么起手

读完上面四份，再在设计工具里搭画布。搭的时候守四条铁律：

  1. 0 裸 HEX：颜色绑变量或严格等于 tokens.json；白色也是 token（neutral/N1）。
  2. 词汇同源：组件名 = 代码库组件名（packages/web-ui 33 件 / packages/mobile-ui NutUI），不造野组件。
  3. 字阶照 spec：Web 12 级 / 移动端 android + ios 双套 9 级；字体 Source Han Sans CN。
  4. 文本必绑 neutral 色，禁默认黑。
Ardot 用户： Web 文件 709697838782860（83 变量双模式 + 33 组件 + 12 级字阶）； 移动端文件 709734372369429（60 变量双模式 + 37 组件 cell + 双套字阶）。 旧文件 701545559030003 / 701218509066139 弃用只读。 MCP 做不到、需人工收尾的：合并变体、发布 Text Style。
4产出与验收

设计稿 = 视觉交付物。验收靠截图自查三条：

  • 0 裸 HEX（颜色都绑到变量上）
  • 字阶正确
  • 组件名与代码一致

前端工程师 → React 生产代码

核心：不手写样式。组件库已消费 tokens.json，样式与规范天然一致。

前端工程师Agent + 组件库 → React 生产代码
1怎么对 Agent 说
用 packages/web-ui（或 mobile-ui）组件库实现 <需求描述>。
引入 globals.css + components.css，只用库内组件拼装，不写自定义样式。
选端web-ui 还是 mobile-ui 起手import 组件库 + 两份 css 门禁validate-static.js 5 门禁全绿
2Agent 读什么
  • components.json —— 组件词汇（叫什么名、有哪些变体），保证和设计端同源。
  • packages/web-ui（33 件）或 packages/mobile-ui（Taro + NutUI）—— 库里已有什么就用什么。
  • 不需要去 tokens.json 抄色值：组件库已经消费过 tokens，色值由 globals.css 提供。
3怎么起手

6

改规范的唯一正确姿势

改真源 → 各链路重新生成 → 总门禁。顺序反了就是漂移。

  1. 改真源：tokens.json（值）或 components.json（契约）。
  2. Web 代码端：cd packages/web-ui → node scripts/map-tokens.js --brand '#新色' → export-static.js → validate-static.js。
  3. 设计端：同步变量值（任何工具同理：先改 token 定义，产物自动跟随）。
  4. 总门禁：node ci-local.js → 期望 81 pass / 0 fail。
禁止： 从任何产物（设计稿 / HTML / 代码）倒推 spec。三条链路各自重新生成，真源只有一份。
7

常见问题

三条封顶。

Q1 · 换品牌色怎么办？

改 tokens.json 的 colors.primary.default → packages/web-ui/scripts/map-tokens.js --brand '#新色' → export-static.js 重新生成。

功能色（成功 / 警告 / 错误 / 运行）固定不随品牌变。

Q2 · 加新组件怎么办？

token 需求写入 tokens.json → packages/web-ui/src/components/ui/ 加 .tsx → components.css 加样式 → export-static.js → validate-static.js 全绿 → 设计端同步加同名组件。

Q3 · 怎么确认没改坏？

跑总门禁 node ci-local.js，期望 81 pass / 0 fail。

单个 HTML 产物另跑 validate-spec.js（0 HIGH）；React 产物另跑 validate-static.js（5 门禁全绿）。
